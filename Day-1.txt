  +-------+  +-------+  +-------+  +-------+  +-------+  +-------+
  | dev-1 |  | dev-2 |  | test-1|  | test-2|  | prod-1|  | prod-2|
  +-------+  +-------+  +-------+  +-------+  +-------+  +-------+
      \          \           |          /          /          /
       \          \          |         /          /          /
        \          \   [SSH Connection]          /          /
         \          \        |        /          /          /
          \          \       |       /          /          /
           \          \      |      /          /          /
            \          \     |     /          /          /
             +----------+----+----+----------+----------+
                              |
                    +===================+
                    |    MASTER NODE    |
                    |-------------------|
                    | >> Install Ansible|
                    | >> Install Python |
                    +===================+
                              |
             +----------------+----------------+
             |                                 |
  +--------------------+          +--------------------+
  | host inventory file|          |    ansible.cfg     |
  | (list of all nodes)|          | (main config file) |
  +--------------------+          +--------------------+

  [!] All commands must be executed on Master Node

+=========================EXPLANATION=========================+
|                                                             |
|  1. MASTER NODE                                             |
|     - Central control machine                               |
|     - Ansible + Python installed here                       |
|     - Sends instructions to all managed nodes               |
|                                                             |
|  2. MANAGED NODES                                           |
|     - dev-1, dev-2   --> Development Servers                |
|     - test-1, test-2 --> Testing Servers                    |
|     - prod-1, prod-2 --> Production Servers                 |
|                                                             |
|  3. SSH CONNECTION                                          |
|     - Master connects to all nodes via SSH                  |
|     - No agent needed on managed nodes                      |
|     - Secure and lightweight communication                  |
|                                                             |
|  4. AGENTLESS                                               |
|     - No software installed on managed nodes                |
|     - Only SSH access is required                           |
|     - Unlike Puppet/Chef which need agents                  |
|                                                             |
|  5. CONFIG FILES (on Master Node)                           |
|     - host inventory file --> Lists all managed nodes       |
|     - ansible.cfg         --> Main Ansible configuration    |
|                                                             |
|  6. SOFTWARE ANSIBLE CAN MANAGE                             |
|     +----------------+                                      |
|     | tomcat 9.0.10  | --> Web Application Server           |
|     | java 21        | --> Programming Runtime              |
|     | maven 3.9.7    | --> Build Automation Tool            |
|     | ....           | --> Any other software               |
|     +----------------+                                      |
|                                                             |

Setting up the host inventory file
Note: By default, in the latest versions we will not have host inventory file in /etc/ansible/hosts path. We need to explicitly create this path and also the inventory file

Step 1 — Create /etc/ansible/ directory
sudo mkdir -p /etc/ansible

Step 2 — Create a config file
sudo nano /etc/ansible/ansible.cfg

Paste this minimal configuration:
[defaults]
inventory=/etc/ansible/hosts
host_key_checking=False

Save & exit.

Step 3 — Create the hosts inventory file
sudo nano /etc/ansible/hosts

Add your hosts:
[dev-servers]
your-ec2-private-ip-here

[test-servers]
your-ec2-private-ip-here

Save & exit.

To verify the connection ----> ansible all -m ping ---> You should see the response from all the 4 worker nodes as "pong"

2. Ansible Modules
These will work based on key-value pairs

"yum" - module name
"user" - module name

States;
yum modules;
install = present
uninstall = absent
update = latest

service modules;
start = started
stop = stopped
restart a service = restarted
enable a service = enabled

key=value 


ansible all -m yum -a "name=docker state=present"
ansible all -m yum -a "name=httpd state=present"
ansible all -a "httpd -v"
ansible all -m yum -a "name=docker state=absent"
ansible all -a "systemctl status httpd"
ansible all -m service -a "name=httpd state=started"
ansible all -a "systemctl status httpd"
ansible all -m service -a "name=httpd state=status"
ansible all -m service -a "name=httpd state=state"
ansible all -m user -a "name=lambo state=present"

=> Ansible Playbooks
A playbook contains task(s)

Playbooks in ansible will be written in YAML format
YAML file starts with --- and ends with ... (optional)
.yml or .yaml
Playbook is case sensitive and indentations are very important

At the beginning of any playbook, it is recommended to write the description (-name:<Description of playbook>)

example 
vi playbook1.yml
---

- name: Playbook to check the connection between the servers
  hosts: all
  tasks:
    - name: Testing the connectivity
      ping:
...

1. Check Playbook Syntax
  ansible-playbook playbook1.yml --syntax-check

2. Check Inventory Connectivity (Ad-hoc way)
  ansible all -m ping

3. Dry Run (Check Mode)
  ansible-playbook playbook1.yml --check
  ansible-playbook playbook1.yml

4. Execute the Playbook
  ansible-playbook playbook1.yml
  ansible-playbook -i hosts playbook1.yml

5. Verbose Output (for debugging)
  ansible-playbook playbook1.yml -v
  ansible-playbook playbook1.yml -vvv

6. List Tasks (Before Running)
  ansible-playbook playbook1.yml --list-tasks
